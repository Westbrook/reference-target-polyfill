01 / Get the files

Install from GitHub

npm install git+https://github.com/Westbrook/reference-target-polyfill.git#main

The package is named reference-target-fallback; it is not published to npm. Replace main with a commit SHA for a repeatable install. The package-import examples below assume a bundler; use URL imports for plain browser modules.

Using browser modules without a bundler

Use the hosted module URLs in place of package imports in the recipes below:

import { hasNativeReferenceTarget } from
  "https://westbrook.github.io/reference-target-polyfill/src/detect.js";

// In reference-target.setup.js:
import { installReferenceTarget } from
  "https://westbrook.github.io/reference-target-polyfill/src/core.js";
import { labels } from
  "https://westbrook.github.io/reference-target-polyfill/src/adapters/labels.js";

The files are ordinary ES modules: detection, core, and a label adapter. The hosted copies follow this repository; for a version you control, vendor the complete src directory at a pinned commit and import from your own paths.

02 / Before components

Load the fallback, then your app

Load bootstrap.js with <script type="module">. Keep installation in its own module so a supporting browser can skip it. The cooperative combobox adapter has a separate loading recipe.

app.js defines components and initializes normally when imported. The installer captures later attachShadow() calls, including closed roots:

const root = this.attachShadow({
  mode: "closed",
  referenceTarget: "control",
});
root.innerHTML = '<input id="control" type="email">';

If your bundler uses sideEffects: false, preserve the setup module as side-effectful. Install once per browser realm.

03 / Choose capabilities

Only the adapters you select

Import each factory from reference-target-fallback/adapters/<module> and add it to the same adapters array. There is no “all adapters” entry point.

Providing public text for names and descriptions 
import { textNames } from "reference-target-fallback/adapters/text-names";

const names = textNames({
  getText(host, kind) {
    return host.getAttribute(
      kind === "label" ? "data-label-text" : "data-description-text",
    );
  },
});
// Add names to the installation's adapters array.

Return a string to opt in, or null to leave a reference alone. The provider receives the public host, never its private target. Call referenceTarget.refresh() after text changes held only in your application’s model.

04 / Submit & reset

Keep the fields inside the form

For a forms-only setup, select formTargets(). Use the same conditional bootstrap from above.

<x-profile id="profile" data-reference-target="form">
  <template shadowrootmode="open" shadowrootreferencetarget="form">
    <form id="form">
      <label>Email <input name="email" type="email" required></label>
    </form>
  </template>
</x-profile>
<button type="submit" form="profile" name="intent" value="save" disabled>
  Save
</button>
<button type="reset" form="profile" disabled>Reset</button>

Native validation, submit/reset events, and the form’s own fields remain in use. In fallback mode, event.submitter is a temporary inner submitter carrying the outside control’s name, value, and form overrides. Read FormData synchronously while it exists.

This forwards actions; it does not associate external data controls or change .form and .elements. Image submitters are unsupported. Try validation, submitter data, and reset ↗

05 / One popup, two references

Give the input real public options

The input controls a listbox and tracks a separate active option. Keep those real elements in its DOM tree, optionally slotted through the component’s shadow root.

Do not skip this setup when hasNativeReferenceTarget() passes. Phase 1 provides one target per root; this provider supplies two. With native Phase 1, only the cooperative adapter stays active and native attachShadow() and root properties remain intact.

Markup and component responsibilities 
<label for="city">City</label>
<input id="city" type="text" role="combobox" aria-autocomplete="list"
       aria-expanded="false" aria-controls="cities" aria-activedescendant="cities">
<x-cities id="cities">
  <div id="city-options" role="listbox" aria-label="Cities" hidden>
    <div id="city-oslo" role="option" aria-selected="false">Oslo</div>
    <div id="city-tokyo" role="option" aria-selected="false">Tokyo</div>
  </div>
</x-cities>

The synchronous provider returns the public listbox inside the referenced host and its active option, or null. Both need unique IDs and the exact roles listbox and option; the active option must be a DOM descendant of the listbox. The host, listbox, option, and input share an actual DOM tree.

The adapter accepts text/search inputs with role="combobox" and a single host ID in aria-controls. It replaces that reference with the listbox ID. If the authored aria-activedescendant also names the host, it tracks the usable active option while expanded and removes the effective attribute otherwise. Absent or directly authored option references remain yours.

Your component supplies filtering, keyboard and pointer interaction, expanded/selected state, focus, and scrolling. Call referenceTarget.refresh() synchronously after popup or active-option changes. Keep focus in the input when navigating options.

This adapter handles content attributes and real public nodes. It does not provide private cross-root reflection, hidden option mirrors, or the proposed Phase 2 API. See the combobox design case and ARIA authoring pattern.

06 / Declarative markup

Leave a hint on the host

For declarative Shadow DOM, keep data-reference-target on the host. Call referenceTarget.hydrate() after the markup is available to discover open roots and read that hint.

<label for="email">Email</label>
<x-email id="email" data-reference-target="control">
  <template shadowrootmode="open" shadowrootreferencetarget="control">
    <input id="control" type="email">
  </template>
</x-email>

The browser must already support declarative Shadow DOM. Hydrate again after changing the host metadata. Existing closed roots need cooperation from code that already holds the root:

const registration = referenceTarget.register(rootKnownToTheComponent, {
  referenceTarget: "control",
});

// When the component no longer participates:
registration.dispose();
07 / Know the boundary

A fallback with a defined scope

  • Accessibility: label naming and text proxies are approximations; comboboxes need a component-provided public listbox and options. Arbitrary cross-root ARIA relationships and full accessible-name computation are outside this package. Test with your browsers and assistive technology.
  • Native primitives: Shadow DOM, MutationObserver, and WeakRef are required. Action adapters use the browser’s existing popover, dialog, and form methods.
  • Encapsulation: the handle exposes no private target resolver. Native reflection, event paths, and full form ownership cannot be recreated here.
  • Detection: hasNativeReferenceTarget() checks the API surface. probeReferenceTarget() adds basic nullable-value and label tests; neither certifies every behavior. The installer declines fallback activation over detected partial native support. The cooperative combobox bridge remains available. force: true is for testing.

Inspect referenceTarget.mode, .statuses, and .activeAdapters for the installed state. To release listeners, observers, adapter changes, and the owned attachShadow() wrapper:

referenceTarget.dispose();
