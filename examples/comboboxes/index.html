These are the input’s actual ID references. The listbox and options share its DOM tree; a closed shadow root supplies the component’s shell.

Behavior & limits

The adapter rewrites aria-controls="cb-host" to the public listbox and aria-activedescendant="cb-host" to its current public option. The component handles filtering, keyboard input, selection, visibility, scrolling, and focus.

This is a cooperative bridge, not the proposed Phase 2 map into private roots. There is one real listbox, with real visible options distributed through a slot. Native Phase 1 still has only one target per host, so Automatic also loads this adapter there.

Browser alone keeps the component interactions but leaves the authored host references unresolved. DOM readouts do not establish screen-reader support; test the browser and assistive technology combinations you ship.

// reference-target.setup.js
import { installReferenceTarget } from 'reference-target-fallback/core';
import { comboboxTargets } from 'reference-target-fallback/adapters/combobox-targets';

export const referenceTargets = installReferenceTarget({
  adapters: [comboboxTargets({
    // The component intentionally exposes only its public nodes.
    getTargets: host => host.getComboboxTargets?.() ?? null,
  })],
});
// The component calls referenceTargets.refresh() after model/render updates.
// bootstrap.js — Phase 1 support does not replace this cooperative bridge.
const { referenceTargets } = await import('./reference-target.setup.js');
await import('./app.js');
// app.js is an ordinary module; it does not need to export a start() method.

Implementation notes & limitations

Fallback scope

The adapter connects editable inputs to component-provided public listboxes and options in the same DOM tree. It does not expose targets inside private roots or implement the proposed Phase 2 target map.

See the combobox problem in the explainer and the ARIA combobox pattern. Verify assistive technology behavior separately.
